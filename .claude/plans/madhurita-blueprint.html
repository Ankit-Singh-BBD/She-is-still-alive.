10 Invariant rules — har chapter me true
1. Model proposes, app validates & authorizes effects.
2. Only evidence earns verified. accepted/started/returned/verified/notified/seen alag hain.
3. Long work durable coordinator ka hai, browser tab ka nahi.
4. One source, many workers/projections — leases + versions prevent competing ownership.
5. View open/close local hai — persistent cancel nahi.
6. Failed dependency → useful limited state, not fake completion. No paid fallback without permission.
7. Observations / inferences / confirmed facts alag rahenge. Corrections affect next behavior.
8. Migrations, auth, provenance, tests preserve — clean-slate deletion nahi.
9. No new dependency without identity/license/compatibility/necessity check.
10. Acceptance tests ko broken behavior pass karane ke liye edit nahi.
✗ Forbidden — “File created → user read it” ya “request sent → delivered” upgrade, invented task list, mock progress, baiography as health.
✓ Required — har completion line verifiedOutcomeId cite kare; failed dependency par limited draft + pending list.
Awareness priorities — kya pehle yaad aaye
  1. Owner goals & commitments
  2. Current tasks, outcomes, blockers
  3. People & relationships — kaun jude hain, kya chal raha hai
  4. Preferences & recent references
  5. Capabilities & component health
  6. World — time, weather, location, calendar, devices — only when relevant, weather is one modifier among many

AGI-like learning = transfer aspiration (lesson from one task helps another) — implemented as typed episodic memory + corrections + retrieval + held-out skill evaluation. Consciousness / unlimited training ka claim nahi.
